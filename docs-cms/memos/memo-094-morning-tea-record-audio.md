# Implemented audio increment

Morning Tea is one original, thirty-second instrumental record. The bounded
[sampler](../../core/music.c) sequences three voices from a shared
[PCM bank](../../core/music_samples.c), generated by
[the original sample script](../../tools/audio/music_samples.py). No external
recordings or full-song PCM are embedded. Fifteen bars at 120 BPM combine keys,
bass, and a soft brush. The final second fades naturally.

The [public contract](../../include/jelli/music.h) uses exact sample cursors and
serial tokens acknowledged after commands apply. Seek reconstructs the waveform
in constant time. Muting still advances playback; pause holds the cursor; stop
rewinds. Rendering is independent of block partition and uses no allocation,
clock, or floating-point arithmetic. The engine owns checkpoint/reward policy.

[SDL](../../ports/sdl/sound_output.c) serializes controls and snapshots using the
audio-device lock. The [ESP adapter](../../ports/esp32/main/sound_output.c) keeps
music and synthesis owned by its audio task; a separate bounded command queue
applies controls between blocks, and a critical section publishes status. A
failed codec submission restores the record cursor and pauses playback. Cursor
progress measures accepted output samples, not independently measured speaker
playback. Hardware DMA may retain a short queued tail.

Each accepted control begins a 64-sample transition from the last music sample
before care mixing. Pause and stop submit a fading tail without crediting more
record samples. Care cues retain their independent queue and duck the record by
half while active. Saturation defines every input combination. The codec uses
its existing maximum ceiling with per-cue and record gains in PCM; physical
loudness equivalence to the previous codec-volume policy is unverified.

# Measured bounds and review artifact

On the macOS host, music state is 12 bytes, command 16 bytes, status 12 bytes,
and transition state 6 bytes. The immutable PCM bank is 448 bytes; note tables
add 88 bytes. Each adapter has two 512-sample PCM buffers (2 KiB total). ESP adds
four command slots (64 bytes plus the SDK queue control structure), retains its
static 4096-byte task stack, and holds the codec mutex for one bounded block.
There is no allocation in the callback or render loop. Native optimized host
measurement rendered 13,230,000 samples in 0.089834 CPU seconds; this is not an
ESP timing guarantee.

Build `jelli_music_export`, then run it with an output WAV path to audition the
same sequencer. The review artifact `build/morning-tea.wav` is mono PCM16 at
22,050 Hz, exactly 661,500 samples / 30 seconds, 1,323,044 bytes. At exported
volume 80 its peak is 7,319. SHA-256:
`4cdc8be5b69aade9e0b42ce99d1d36536db56aca851fa1759a14a7cbf353bef3`.
This is a generated audition file, not a claim of subjective listening or a
physical speaker test.

# Validation and remaining uncertainty

[Core tests](../../tests/test_music.c) cover duration, block partition equality,
seek equivalence, muted progress, controls/serials, invalid commands, output
bounds, clipping, and transition endpoints and monotonic ramps.
[SDL dummy-device tests](../../ports/sdl/test_music_output.c) cover callback progress,
pause stability, care coexistence, exact completion, and closed-device rejection.
[Exporter tests](../../tests/test_music_export.py) parse the real WAV and check
format, length, non-silence, and fade. Standalone strict compiler tests and these
three focused tests passed before integration.

Initial clang-tidy found implicit narrowing in the saturating mixer and implicit
widening of a test length expression. Explicit saturation branches and a
`sizeof`-derived test length remedied those findings. Full validation results
will be recorded below. Firmware build is delegated to the prepared integration
checkout. No flash, physical audio, or device timing test was performed here.

Focused native and ASan/UBSan reruns passed all three audio tests after the
transition change. Repository documentation validation and repair both passed.

Cppcheck additionally rejected a transition parameter shadowing the sampler
function; renaming the parameter resolved it. The SDL adapter test lives with
the port because generic portable-C analysis intentionally omits SDL headers.

Final branch validation: host 96/96, core-only 43/43, and full ASan/UBSan
96/96 passed. The audio-specific tests were rerun after the transition and
adapter-test path changes and passed 3/3 in native and sanitizer builds.
